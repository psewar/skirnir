# Changelog

## Node tools (included in v0.31.0)

- `agent/Set-OllamaLoopback.cmd` binds Ollama on a Windows node to loopback in one step (TM-11, ADR-0072): double-click, it asks for administrator rights itself and starts despite the default execution policy. It detects whether Ollama is the agent's child or a user's desktop app, sets `OLLAMA_HOST=127.0.0.1:11434` there, restarts Ollama, verifies that every listener is a loopback address (else restores the previous state) and disables firewall rules that only opened Ollama. It refuses while other machines are connected to Ollama (`-Force "<reason>"`); `-Check` only reports. Router and agent versions are unchanged.

## Development tooling (pinning included in v0.26.1, the rest in v0.27.0)

- Agent revocation and enrollment at the wire (TM-07): `test/selftest_agent_revocation.py` signs the tunnel challenge with an Ed25519 key like an agent and checks that revoking ends a waiting and a streaming request with the reason `revoked`, tells the agent, closes the connection and removes the node; that the revoked key is refused on reconnect; and that new keys beyond the per-address limit are refused with 1008 while an approved key still connects.
- Route-inventory tests (TM-09): the session and memory self-tests enumerate every registered route from the router, so a route added later is covered automatically. No route answers without an identity (401 under `enforce`, never 2xx under `observe`, the memory backend is never reached), and every owner-scoped session-store call uses the authenticated caller. Fault injection (a fixed owner, a skipped identity check) makes both tests fail.
- Monitoring: Prometheus v3.15.1 → v3.16.0 (#99, digest-pinned; the first image update proposed by Dependabot's docker-compose ecosystem). The stack's flags, scrape configuration and retention are unaffected by the 3.16 changes.
- Third-party references are pinned (ADR-0055, TM-16): workflow actions to commit SHAs, `govulncheck` and `pip-audit` to versions, the monitoring images and the decision-service base images to digests (the running monitoring stack already used exactly these digests). `test/check_pinned_references.py` enforces it in CI; Dependabot also updates the image digests. `pip-audit` additionally audits the session-store, development, memory-test and rerank-server requirements.

## Development tooling (since v0.25.1, included in v0.25.2)

- Run an independent pre-merge evidence check and restrict the Dependabot exemption to existing dependency versions (ADR-0050, accepted).
- Weekly full security reviews resume from the previously reviewed chunks (ADR-0049, accepted).
- Add the versioned threat model, risk register and repository security-review skill (ADR-0047).
  Every PR/update requires a change-bound review record; CI rejects missing/stale evidence and expired acceptances.
  Optional, read-only model reviews run after PR CI and weekly when explicitly configured; otherwise report skipped.
  Added negative security regressions. Router/agent versions and runtime configuration are unchanged.
- The advisory recheck after PR CI compares against the PR's base commit from the event instead of the moving
  default-branch head; a PR merged before the recheck started showed a false "stale record" failure.
