# Changelog

Releases are tagged `vX.Y.Z` on this repository and carry the agent binaries as assets. Router and agent have their own
version numbers; this table maps them. Details and the German summary are in each release's notes.

| Tag | Date | Router | Agent | What changed |
|---|---|---|---|---|
| [v0.12.0](https://github.com/psewar/skirnir/releases/tag/v0.12.0) | 2026-10-01 | 0.6.0 | 0.16.0 | **Anthropic Messages API.** `POST /v1/messages` (streaming and not) and `/v1/messages/count_tokens`, translated to `/api/chat` through the scheduler, so Claude Code and other Anthropic clients get roles, the tier's context (or the loaded one), warm first, `gpu_busy` waiting and tool-call rescue instead of Ollama's own `/v1/messages`, which knows no `num_ctx` and reloads the model. Streaming follows Anthropic's event order, with `ping` events while a long prompt is being processed (`router.anthropic.keepalive_s`, 15 s). No capacity is HTTP 529 `overloaded_error` with `Retry-After`, which Claude Code retries by itself. Client identity also via `x-api-key`; `GET /v1/models` answers in Anthropic form when the request carries `anthropic-version`. New selftest `selftest_anthropic_messages.py` in CI. |
| [v0.11.1](https://github.com/psewar/skirnir/releases/tag/v0.11.1) | 2026-10-01 | 0.5.0 | 0.16.0 | The agent keeps the Windows uninstall entry of Ollama current. winget and UniGetUI read the installed version only from that entry; since the agent swaps Ollama's files itself, it kept showing the old version, so winget offered every release and the installer then failed against the Ollama running as a child of the service. The agent now sets `DisplayVersion` and `DisplayName` after every swap and reconciles them 30 s after start and hourly (a user's registry hive is only loaded while that user is signed in). Tray installations are left alone. Recommended on such nodes: `winget pin add --id Ollama.Ollama --blocking`. |
| [v0.11.0](https://github.com/psewar/skirnir/releases/tag/v0.11.0) | 2026-10-01 | 0.5.0 | 0.15.0 | **Ollama swap only after the router's release.** The node keeps serving requests while the agent downloads and verifies the new Ollama; then the agent reports `ready`, the router takes the node out of routing, waits until no request is running and sends `ollama-swap`. Without the release nothing is swapped (agent waits 30 min, router gives up after 25 min if the node does not drain). No prewarm while an Ollama update runs (before, a prewarm loaded a large model that the swap stopped 30 s later), one prewarm when it is done. The *Ollama auto-update* option is greyed out for nodes whose Ollama runs as a tray app. Agents before 0.15.0 keep the old behaviour (node drained from the order on). |
| [v0.10.1](https://github.com/psewar/skirnir/releases/tag/v0.10.1) | 2026-09-30 | 0.4.1 | 0.14.1 | Fix for 0.14.0: with nothing loaded the agent sent `ps: null` (a Go nil slice) because it only took over a list when it changed, and the router discarded the report and kept the node offline until the last valid report expired. The agent now always sends lists and counts its first answer as a change; the router treats `null` as an empty list and falls back to polling at once when a report is unusable. New selftest `selftest_ollama_push.py`. |
| [v0.10.0](https://github.com/psewar/skirnir/releases/tag/v0.10.0) | 2026-09-30 | 0.4.0 | 0.14.0 | **The agent reports Ollama's state instead of the router polling it.** The agent watches its local Ollama (loaded models every second, installed models every 5 s) and sends installed models, loaded models and whether Ollama answers as a new tunnel frame `OLLAMA`, immediately on every change and in full at least every 30 s. After three failures in a row it reports `up: false` with the reason, and the router takes the node out of routing at once. While these reports are fresh the router no longer polls the node; older agents and static nodes are still polled every 5 s. Node state shows `ollama_source: push|poll`. Poll and push share one evaluation path in the router. Two router fixes the faster state exposed: a delayed prewarm now only runs for the free transition it was planned for (before, a prewarm planned at one transition fired right after the next one), and the busy unload safety net runs from the one-second tick instead of after each poll. Two end-to-end checks now expect the 0.3.7 behaviour (a role request with a smaller context reuses the loaded one). |
| [v0.9.6](https://github.com/psewar/skirnir/releases/tag/v0.9.6) | 2026-09-30 | 0.3.8 | 0.13.0 | **The agent reports its children's GPU memory; loaded context is reused.** The heartbeat carries `children_vram_mib`: dedicated GPU memory of every running child except Ollama, measured per process with the Windows counter `\GPU Process Memory(*)\Dedicated Usage` over all processes in the child's job object (`skirnir-agent gpu` lists them; Windows only). The router no longer counts it as foreign VRAM and leaves it out of the learned baseline; a speech-to-text child on CUDA (2.5 GiB) otherwise pushed the node over the busy threshold (desktop plus a light game 3.6 GiB, with the child 6.2 GiB). Router 0.3.7: a role request with a smaller `num_ctx` than the loaded context (up to the tier's limit) gets the loaded context, because some models do not share a runner across `num_ctx` values and reloaded on every switch between a 64k and a 128k client (7 to 10 s). New self-tests `selftest_kontext_teilen.py` and `selftest_kinder_vram.py` in CI. |
| [v0.9.5](https://github.com/psewar/skirnir/releases/tag/v0.9.5) | 2026-09-30 | 0.3.6 | 0.12.1 | **Real VRAM measurement, fixed.** The 0.3.5 measurement read the empty baseline too early: after unloading a big model `/api/ps` is empty at once, but nvidia-smi frees the memory seconds later, so two equal heartbeats still showed the full card and the first point came out negative (weights 0.1 GiB in the catalog). It now waits until at least 90 % of what `/api/ps` reported is freed, waits for loads started by others (the prewarm after the previous measurement), checks that only the measured model is loaded, and discards a point that is smaller than Ollama's own figure (up to three tries per point; a measurement that stays implausible writes nothing). Points that spill into system RAM count with the spilled part instead of being dropped, so the catalog knows the model does not fit at that context. Measured entries no longer get the 0.8 GiB fit overhead (it compensated for `/api/ps`); the budget reserve stays. Re-measure models measured with 0.3.5. |
| [v0.9.4](https://github.com/psewar/skirnir/releases/tag/v0.9.4) | 2026-09-30 | 0.3.5 | 0.12.1 | **Why no node, and real VRAM numbers.** A request that gets no node now carries a reason code instead of a bare *no node available*: `gpu_busy`, `node_offline`, `node_draining`, `node_failing`, `vram_full`, `model_too_large`, `model_missing` or `attempt_failed`, with `Retry-After` where waiting helps and the obstacle per node (need, budget, foreign VRAM). OpenAI clients find it in `error.code` / `error.retry_after` / `error.skirnir.blockers`. `gpu_busy` also covers a node that is *free* while foreign VRAM (a game) takes exactly the missing room. New `GET /v1/skirnir/availability/<model>` (client auth, read-only) tells a waiting client when a request would get a node. The decision log shows the reason (yellow for `gpu_busy`). Router 0.3.5: `/admin/measure` measures a model's real footprint from the agent's nvidia-smi values (everything unloaded, baseline read, model loaded, at 8k, 32k and every context a role uses) instead of `/api/ps`, which reports only part of it (21.0 instead of 26.4 GiB for a 35B MoE at 196k). Loaded models count with that real footprint in the budget, in foreign VRAM and in the unload hold; without a real measurement nothing changes. The state machine pauses during a measurement; saving the catalog in the UI keeps the measurement. After upgrading, measure the models you route to and lower a node's `foreign_vram_baseline_gib` if it was raised to hide the unreported part. |

| [v0.9.0](https://github.com/psewar/skirnir/releases/tag/v0.9.0) | 2026-09-26 | 0.3.0 | 0.12.0 | **Ollama updates through the router.** With Ollama running as a child of the agent service, the tray app's updater no longer applies; the router now checks the latest Ollama release (GitHub API + `sha256sum.txt`), shows it per node in the *Agents* tab and, with the per-node policy *Ollama auto-update*, updates nodes inside a night window (`modes.ollama_update`, default 02:00 to 05:00), canary first, only when free.
